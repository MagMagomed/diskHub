# DiskHub

Локальное веб-приложение для загрузки и хранения фотографий и других файлов.
Пользователи регистрируются по адресу электронной почты и паролю, после чего
видят только файлы своего аккаунта. Отображаемое имя можно задать при
регистрации и изменить позднее в шапке личного пространства; для входа
используется адрес электронной почты.

## Запуск

Требуется Node.js 18 или новее.

```bash
npm install
npm run dev
```

Откройте адрес Vite, показанный в терминале (обычно `http://localhost:5173`).
Файлы каждого аккаунта сохраняются в отдельной папке
`uploads/<идентификатор-пользователя>/`. Папки создаются автоматически.
Имена файлов, включая кириллицу, сохраняются без потери кодировки.
Данные аккаунтов и хеши паролей находятся в `data/users.json`; пароль
сохраняется в виде хеша scrypt с уникальной солью. Эти данные и загруженные
файлы исключены из Git.

Для production-сборки выполните `npm run build`, затем `npm start`. Приложение
будет доступно на `http://localhost:3001`.

За одну загрузку можно отправить до 20 файлов размером не более 100 МБ каждый.
Пароль должен содержать от 10 до 128 символов. Сессия хранится в защищённой от
чтения JavaScript cookie сроком на 7 дней; после перезапуска сервера потребуется
войти снова. Файлы, оставшиеся в корне `uploads/` от версии без аккаунтов, не
показываются ни одному пользователю.

В форме регистрации можно сгенерировать случайный пароль и после регистрации
или входа сохранить его в менеджере паролей браузера. Сохранение доступно в
совместимых браузерах на защищённом соединении; если браузер не поддерживает
Credential Management API, приложение сообщит об этом.
Имя пользователя может содержать от 2 до 40 букв, цифр, пробелов, точек,
дефисов или подчёркиваний.

## Роли и права доступа

У нового аккаунта роль `Customer`: он может просматривать, загружать и удалять
только свои файлы. `System Customizer` может просматривать список всех аккаунтов,
их роли и файлы, а также скачивать и удалять файлы пользователей. Администратор
видит отдельную панель управления после входа.

Повысить роль можно только с доступом к серверу. Остановите приложение и
выполните команду из корня проекта:

```bash
npm run role:set -- admin@example.com "System Customizer"
```

Для назначения обычной роли используйте `"Customer"`. После изменения роли
перезапустите сервер, чтобы обновить активные сессии. Роли не принимаются из
запроса регистрации и не изменяются пользователем через API.

## Публикация в локальном IIS

После установки Node.js выполните из корня проекта:

```powershell
npm install
npm run build
powershell -ExecutionPolicy Bypass -File .\deploy\iis\Install-DiskHubIis.ps1
```

Скрипт запросит повышение прав Windows, включит необходимые компоненты IIS и
установит официальные, подписанные Microsoft модули URL Rewrite и Application
Request Routing, если их ещё нет. Затем он создаст сайт `http://localhost:8080/`
и HTTPS-привязку `https://diskHub.com/`; существующие сайты и порт 80 не
меняются. Для HTTPS скрипт создаёт локальный сертификат и отдельный корневой
сертификат удостоверяющего центра. Закрытый ключ центра остаётся на сервере;
публичный сертификат для доверия клиентских устройств сохраняется в
`C:\ProgramData\DiskHub\DiskHub-Local-Network-RootCA.cer`.

IIS отдаёт production-файлы из `C:\inetpub\DiskHub` и передаёт запросы `/api`
на Node.js, привязанный только к `127.0.0.1:3001`. Защищённая сессионная cookie
для HTTPS-адреса помечается `Secure`. Сервер Node.js запускается при входе
пользователя в Windows через Планировщик заданий. Данные аккаунтов и файлы
остаются в папках `data/` и `uploads/` проекта и не копируются в каталог IIS.

### Доступ с устройств локальной сети

1. Закрепите за сервером постоянный LAN-IP (DHCP reservation) в настройках
   роутера. В конце установки скрипт выводит доступные приватные IP-адреса;
   выберите адрес Wi-Fi или Ethernet, подключённого к нужной сети.
2. Настройте локальную запись DNS типа A: `diskHub.com` → LAN-IP сервера.
   Если роутер не поддерживает локальные DNS-записи, добавьте эту же запись в
   файл `hosts` каждого клиента (`C:\Windows\System32\drivers\etc\hosts` в
   Windows; редактировать от имени администратора). Не меняйте публичную DNS
   запись и не настраивайте переадресацию портов из интернета.
3. Скопируйте `DiskHub-Local-Network-RootCA.cer` с сервера на устройство
   доверенным способом и установите его как доверенный корневой сертификат.
   В Windows запустите PowerShell от имени администратора:

   ```powershell
   Import-Certificate -FilePath .\DiskHub-Local-Network-RootCA.cer `
     -CertStoreLocation Cert:\LocalMachine\Root
   ```

   На других ОС импортируйте сертификат в системное хранилище доверенных
   корневых центров сертификации. Без этого браузер покажет предупреждение о
   сертификате. Не копируйте с сервера и не распространяйте закрытый ключ
   корневого центра сертификации.
4. Установщик добавляет правило брандмауэра только для HTTPS-порта 443 и
   удалённых адресов локальной подсети; порт не открывается для подключений из
   интернета.
5. Откройте `https://diskHub.com/`. После изменения кода повторно выполните
   сборку и скрипт установки.

Адрес `diskHub.com` должен разрешаться в LAN-IP сервера только внутри вашей
сети. Локальная DNS-запись не подтверждает владение публичным доменом, а
созданный сертификат доверен только на устройствах, куда вручную установлен
корневой сертификат.
